Cases that decide the model

Candidate decision

Envelopes are exact reservations; native layouts are later proofs

  • The Layout Module consumes only the verified planning closure, canonical assignment, and Architecture Planning Contract. Its one meaningful result is a verified Logical Image Layout or layout conflict evidence returned to the enclosing Image Planning Module.
  • Each logical allocation has a stable identity, semantic owner, provenance, lifetime, protection class, placement, count, profile-defined byte envelope, and envelope alignment. It never carries a native type size or backend handle.
  • Canonical region order, stable allocation identity, alignment padding, guard reservations, and page rounding determine one layout independent of input traversal order. No best-fit heuristic or hidden optimization objective participates.
  • The cost ledger attributes payload, multiplicity, alignment padding, guard pages, and region rounding exactly once. Shared overhead is charged to the contract rule that caused it rather than guessed onto a nearby Creator declaration.
  • Layer 2 rejection means the verified envelopes cannot fit the planning contract. Layer 3 must prove every concrete Target ABI Layout fits its envelope; exceeding an admitted envelope is a Defect, never a new Creator rejection.
  • The verified layout exposes symbolic regions and relative offsets to trusted later Modules. Creator inspection receives cost and provenance observations, never pointers, native layout, candidate search state, or reusable planning artifacts.
