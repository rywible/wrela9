# Preserve actor semantics and rebuild the executor

The original round-robin and universally fail-fast admission details recorded below were later revised: [ADR-0029](./0029-use-compiler-planned-cyclic-scheduler-service.md) selects compiler-planned cyclic service, while the accepted Language Core distinguishes waiting `send` from immediate `try_send`. The remaining decision—to preserve the Actor model while replacing the executor and keeping scheduling guest-owned—still stands.

Wrela 9 will preserve Wrela 8's intended actor model as the semantic destination: bounded FIFO mailboxes, non-reentrant Turns, deterministic round-robin scheduling per core, static activation storage, fail-fast admission, structured Groups, explicit fixed core placement, and bounded cross-core transport without priorities, migration, or work stealing. Wrela 8's documentation and selected golden tests will serve as behavioral inputs, but each behavior must be explicitly Adopted, Revised, or Discarded before it becomes a Wrela 9 contract, and its scheduler implementation will not be ported intact. Wrela 9 will instead build a target-neutral continuation representation and guest-owned executor behind a narrow VM ABI adapter, because the old runtime is coupled to AArch64 code generation, fixed generated stub pools, scheduler-visible VMM state, and incomplete cancellation cleanup. The VMM will deliver VM ABI events and park or wake cores but will not inspect Actor, mailbox, or scheduler memory.
