# Keep game content in the Image and use an Event Store

All executable code, system software, and game assets are immutable parts of the Image and contribute to its digest. They are loaded as Image content rather than exposed as a separate Cartridge block device. Mutable persistent state is represented through the Image's Event Store rather than a save-specific capability, filesystem, or raw block API. Its storage engine uses an optional writable Virtio-Block volume, whose host backing file is an implementation detail.

The Event Store exposes one ordered history of immutable Events. A Creator submits one or more Events as an atomic Event Transaction. One store-owning Actor orders transactions and may aggressively group several of them until a fixed delay, transaction-count, or byte bound is reached, while preserving every Creator-declared transaction boundary. It acknowledges a transaction only after the corresponding data and commit metadata are durable on the block device. Pure bounded Projections derive in-memory state by applying every committed sequence exactly once. This preserves reproducible game artifacts while allowing durable state to evolve without changing the Image.
