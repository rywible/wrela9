# Link standard objects with pinned LLD

Cranelift and authenticated runtime compilation will emit standard target ELF objects, which a pinned `ld.lld` links under a compiler-generated target script before a small Wrela packager validates and wraps the result as an Image. ELF is only a host-side interchange; the guest never loads it. The link contains no external libraries or unresolved symbols: any Cranelift-requested helper must be lowered directly or supplied by a finite sealed Image-owned runtime allowlist. Wrela will not initially implement a private relocatable format or general linker, because doing so would recreate a large part of the backend complexity that adopting Cranelift is intended to remove. Pinning LLD instead of invoking the host-default linker preserves controlled cross-target behavior and repeatable artifacts.
