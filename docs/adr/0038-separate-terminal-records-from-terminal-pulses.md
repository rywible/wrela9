# Separate terminal records from terminal pulses

The VM ABI will use mandatory dedicated terminal infrastructure to send canonical bounded lifecycle and Image Result frames through a reliable generic `virtserialport`, then use stock `pvpanic-pci` to emit the final QEMU Panic or guest-shutdown event. `Ready` and controlled termination require validated bounded launcher acknowledgments; a missing final ACK becomes `ShutdownFailed` without recursive reporting. Panic makes one preallocated best-effort submission and never waits, while concurrent core Panic slots are arbitrated in stable logical and core order before the terminal pulse when peers can be stopped. One sealed latch owns finalization, and the launcher's pre-Ready versus running state distinguishes `BootFailed` from later shutdown. No single stock device provides both structured data and a terminal event, so this split avoids parsed console text, semihosting, architecture-specific debug ports, custom QEMU devices, and host-issued termination masquerading as a guest result.
