# Defer external-tool authentication until distribution

The current Wrela version is a local developer checkout for its builders, so it will treat QEMU and LLD as ordinary installed prerequisites rather than constructing a machine-local authenticated toolchain. `Build` resolves `ld.lld` through `PATH` when needed, and the launcher similarly resolves `qemu-system-aarch64`; each records the resolved path and reported version and reports absence or invocation failure as a host problem. There is no setup operation, lockfile, executable hash, dynamic-dependency traversal, signature inspection, macOS-build binding, or automatic re-locking. Repeated-build reproducibility is scoped to one unchanged local installation. Vendoring, exact identity, distribution, signing, and cross-machine reproducibility return together only when Wrela has a real distribution product. This supersedes the current-developer-checkout authentication requirements implied by ADR 0003, ADR 0004, and ADR 0035 without changing their choices of unmodified QEMU, versioned machine configurations, standard ELF objects, or LLD.
