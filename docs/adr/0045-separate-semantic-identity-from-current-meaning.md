# Separate Semantic Identity from current meaning

Wrela will give every named semantic declaration a closure-scoped identity derived from its defining Module, owner chain, declaration kind, and name, while representing its current signature and body meaning through separate fingerprints. Canonical structured keys are authoritative; versioned domain-separated XXH3-128 digests are opaque observations, full-key comparison detects collisions, and private dense indexes never escape their artifact. One immutable Identity Catalog owns those correspondences for a compilation revision and every compiler phase carries rather than reconstructs its upstream identities.

Ordinary body, signature, visibility, documentation, and ordering edits preserve identity but change relevant fingerprints, while renaming, moving, or changing declaration kind creates a new identity. Mutually exclusive compile-time alternatives with the same owner, name, and kind share one identity; selected alternatives and concrete existential families change fingerprints instead. Type identity, executable Specialization identity, generated-definition identity, anonymous source-site identity, and compact Image-local ordinals remain distinct domains with explicit ownership and stability rules.

This trades content-addressed simplicity, hidden persistent UUIDs, and globally comparable IDs for Source Transactions that can recognize the same declaration across ordinary edits, safe stale-artifact detection, deterministic parallel compilation, and one deep compiler identity seam that does not expose traversal or storage accidents. Compiler identities are deliberately excluded from durable Event, Store, and other production schema contracts, so identity-schema changes and source refactors cannot reinterpret persisted gameplay data.
