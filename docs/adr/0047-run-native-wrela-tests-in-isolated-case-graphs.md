# Run native Wrela tests in isolated Test Case Graphs

Wrela will compile dedicated Wrela Test declarations into one real Test Image for each Project with `src/test.wr`. Every stateful case owns a closed build-known Test Case Graph whose Actors and storage exist for the Image lifetime but remain dormant until activation; cases share immutable code and semantically invisible runner machinery, never reachable mutable state or observable Facility endpoints. The initial runner executes cases serially, while semantic isolation permits later compiler-controlled storage overlay or parallel execution without author annotations. This preserves Wrela's closed topology and native guest execution while avoiding a QEMU launch per case, runtime Actor creation, global fixture reset, and order-dependent tests.

Test setup stays local to each declaration, suites are imported and registered explicitly from `src/test.wr`, and Test-only Projects are valid. Each case reports Passed or Expectation Failed only after its root Group quiesces; Panic terminates the Test Image, and one complete typed Test Report is ordered by canonical Test Identity rather than execution order. The exact construction-clause syntax, suite export form, registration completeness, and Test Identity derivation remain Layer 1 decisions, but they must preserve this separation between effect-free build-known construction and runtime test behavior.

This revises ADR-0041's statement that `src/image.wr` is the only root-level source. It remains the only Deployment root; `src/test.wr` is the sole additional root and cannot be imported or merged into the Deployment closure.
