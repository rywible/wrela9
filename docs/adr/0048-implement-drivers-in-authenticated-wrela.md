# Implement Drivers in authenticated Wrela

Wrela Drivers will be substantial authenticated Wrela Modules compiled through the ordinary semantic IR and Cranelift pipeline. Facility planners, rather than Creator source, select and wire those Modules and grant each exact Module identity only its registered Compiler Primitives. Creator Wrela gains no FFI, raw pointers, inline assembly, linked libraries, or general trusted mode. Only effects that safe Wrela cannot express—such as MMIO, interrupt and fault entry, barriers, and context switching—remain in minimal compiler-owned architecture primitive Adapters implemented through Rust, assembly, or direct lowering.

Driver protocol logic therefore receives native Wrela Tests, while the Compiler Distribution's private Driver Conformance Projects boot real Drivers against controlled QEMU devices and disposable backends. Local development authenticates these version-controlled Modules through an internal registry without certificates or signing. This keeps most runtime behavior inside the language being built, confines unsafe implementation to a narrow auditable floor, and preserves real device conformance without exposing Driver construction or host-step authority to Creator Projects.
